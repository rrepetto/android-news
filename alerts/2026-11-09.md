# Android Security Watch — 2026-11-09 (UTC)

## 🔴 Alta: Poisoned Source — explotación real de Chrome Android mediante watering holes y cadena de suministro web

- **ID estable:** `https://www.sekoia.com/blog/poisoned-source-apt29-watering-holes-targets-mobile-devices-with-n-day-exploits`
- **Fecha de investigación:** 2026-11-04; **fecha de alerta:** 2026-11-09.
- **Resumen técnico:** Sekoia documentó una campaña observada desde mediados de octubre de 2026, atribuida con confianza moderada-alta a APT29, que inyectó JavaScript en sitios legítimos y dominios imitadores y comprometió el script de analítica Plerdy SEO Tracker entre el 27 de agosto y el 3 de septiembre. El loader perfila navegador/dispositivo y entrega una cadena Android que explota **CVE-2026-3910** (RCE en renderer Chrome) y **CVE-2025-27038** (driver Qualcomm Adreno, escape de sandbox y elevación de privilegios). El payload **AndroSnitch** extrae cookies, credenciales e historial de Chrome y contraseñas Wi-Fi, sin persistencia. La cadena aborta explícitamente para Samsung SM-S938B. Se trata de explotación en campaña de vulnerabilidades ya parcheadas, no de zero-days.
- **Afectación:** Chrome Android versiones **139–145**, con exclusión explícita de **143** según el servidor de explotación analizado, sobre dispositivos con driver Adreno vulnerable. La investigación no publica un listado exhaustivo de Android OS/patch levels; no debe inferirse que todos los dispositivos con esas versiones de Chrome sean explotables. Los sistemas completamente actualizados no son vulnerables a esta cadena según Sekoia.
- **Significado antifraude:** confirma compromiso de sesiones web y robo de credenciales desde un navegador móvil a través de páginas legítimas comprometidas, sin APK maliciosa ni interacción adicional. El escape del sandbox evidencia que la ausencia de root visible o malware persistente no descarta una sesión previamente comprometida. **No hay bypass de Play Integrity demostrado**.
- **Acción defensiva:** priorizar actualización de Chrome y parches del driver GPU/firmware, revisar sesiones y tokens web ante exposición, aplicar rotación/revocación cuando corresponda, correlacionar IOCs de Sekoia con telemetría de red y señales de sesión; no tratar el parche del navegador como sustituto de actualizaciones de firmware GPU. Evitar convertir este IOC específico en regla universal de bloqueo.
