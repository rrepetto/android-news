# Android Security Watch — 2026-10-27

## Alta: AuthMask — una app Android sin permisos podía robar tokens de Microsoft Authenticator (CVE-2026-80097)

- **Fecha del análisis técnico nuevo:** 2026-10-23 (Enclave / Ofek Levin); difusión ampliada el 2026-10-26. **CVE y parche:** 2026-09-08. Se trata de nueva evidencia técnica sobre una vulnerabilidad ya corregida, no de un zero-day sin parche.
- **Identificador estable:** `CVE-2026-80097`; fuente canónica: https://enclave.ai/blog/authmask-we-made-microsoft-authenticator-hand-over-tokens
- **Severidad:** Alta (CVSS 8.6). No hay evidencia pública de explotación activa.
- **Resumen técnico:** La Activity exportada `com.microsoft.identity.client.AccountChooserActivity` de Microsoft Authenticator aceptaba solicitudes de autenticación mediante Intent. Una app maliciosa sin permisos Android, sin root y sin modificar el dispositivo podía iniciarla con `startActivityForResult`, atribuirse el UID, package name, client ID y redirect URI de una aplicación legítima de Microsoft instalada (por ejemplo, Teams), y solicitar tokens del broker. La comprobación del redirect URI se hacía contra la firma del *paquete declarado* por el atacante, en lugar de vincular la solicitud con la identidad real del proceso llamador. La Activity devolvía al iniciador tokens de acceso y actualización, además de otros datos de autenticación. En las pruebas, los tokens proporcionaron permisos delegados sobre correo, archivos, calendarios y otras APIs de Microsoft 365.
- **Importancia para antifraude:** Demuestra una evasión real del aislamiento lógico entre aplicaciones a través de un componente exportado que confía en identidades aportadas por Intent, aun sin root, Accessibility, overlays ni permisos peligrosos. Es directamente relevante para apps financieras con Activities/Services exportados, brokers de autenticación, flujos SSO y componentes que validan firmas: verificar la firma de un paquete *declarado* no demuestra que el llamador sea ese paquete. No se trata de un bypass de Play Integrity ni de un defecto general del sandbox de Android.
- **Afectación:** Microsoft Authenticator para Android anterior a **6.2606.4246**, con una cuenta de trabajo iniciada; el investigador también requirió una app legítima de Microsoft instalada para suplantarla. No depende de una versión específica de Android ni de un nivel de parche del sistema operativo. Microsoft corrigió el problema antes de la publicación técnica.
- **Acción defensiva:** Actualizar Microsoft Authenticator a **6.2606.4246 o posterior**. En entornos con exposición previa, evaluar revocación de sesiones/refresh tokens y auditoría de accesos según el riesgo, ya que instalar el parche no revoca tokens previamente sustraídos. Auditar Activities y Services exportados que entreguen credenciales o ejecuten operaciones sensibles; derivar la identidad del llamador de datos verificados por el sistema y asociar UID, paquete y certificado al mismo principal, nunca a extras controlados por el cliente. Probar intent spoofing y validaciones de origen en flujos SSO.
